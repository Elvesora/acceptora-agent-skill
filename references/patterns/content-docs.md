# Content and documentation pattern

Apply to articles, product copy, guides, references, campaigns, metadata, and rendered documentation.

## Coverage prompts

- Confirm the intended audience, goal, scope, tone, and required call to action.
- Verify factual claims against supplied or authoritative sources; flag unsupported facts.
- Check completeness, structure, headings, examples, and consistency with current product behavior.
- Test links, anchors, downloads, code samples, and commands.
- Inspect rendered formatting on relevant desktop/mobile surfaces.
- Verify title, description, canonical/SEO fields, social metadata, and alternative text when changed.
- Check dates, versions, pricing, routes, API fields, and screenshots for staleness.
- Confirm draft/publish state and that no unapproved content was changed.

Use `content:` for provider objects or documents, `file:` for repository sources, `route:` for rendered URLs or screens, and `config:` for metadata. Do not invent source support or imply publication when only a local file changed.
